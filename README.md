# منصة التحليل المالي والتشغيلي للاتحادات — النسخة المتصلة بقاعدة بيانات

هذا المشروع يحوّل النسخة السابقة (ملف HTML واحد يقرأ إكسل محلياً) إلى تطبيق ويب حقيقي:
- **الواجهة** (`public/index.html`) — نفس التصميم والتحليل، لكنها الآن تجلب البيانات من سيرفر بدل ملف إكسل.
- **السيرفر** (`server/`) — Node.js + Express، يتحقق من تسجيل الدخول ويقرأ من قاعدة بيانات SQL.
- **قاعدة البيانات** — PostgreSQL عبر **Supabase**، بأربع جداول: `federations`, `activities`, `financial`, `reviewers`.

> **ملاحظة مهمة**: GitHub نفسه (أو GitHub Pages) يستضيف ملفات ثابتة فقط — لا يمكنه تشغيل سيرفر Node أو الاتصال بقاعدة بيانات. لذلك سننشر الكود على GitHub، ثم "نشغّله" على منصة استضافة تدعم Node.js (مثل Render أو Railway)، وهي التي تتصل فعلياً بـ Supabase.

---

## 0) هيكل المشروع

```
federations-platform/
├── public/
│   └── index.html              ← الواجهة (تُقدَّم مباشرة من السيرفر)
├── server/
│   ├── server.js                ← نقطة الدخول: تسجيل الدخول + جلب البيانات
│   ├── db.js                    ← الاتصال بـ Supabase (PostgreSQL)
│   ├── schema.sql                ← أوامر إنشاء الجداول (+ بيانات تجريبية اختيارية) — تُلصق في SQL Editor بـ Supabase
│   └── import-from-excel.js     ← استيراد ملف الإكسل القديم إلى قاعدة البيانات (تشغيل لمرة واحدة)
├── package.json
├── .env.example                 ← انسخه إلى .env واملأ رابط الاتصال من Supabase
└── .gitignore
```

---

## 1) إنشاء الجداول في Supabase

أنت بالفعل فاتح **SQL Editor** بمشروعك في Supabase. اعمل التالي:

1. افتح ملف `server/schema.sql` من هذا المشروع.
2. انسخ **محتواه كاملاً**.
3. الصقه في نافذة SQL Editor (مكان "Untitled query").
4. اضغط **Run** (أو Ctrl+Enter).

بيُنشئ لك الجداول الأربعة، وبيضيف بيانات تجريبية بسيطة (3 اتحادات + مراجعَين) حتى تقدر تجرب النظام فوراً بعد النشر. إذا ما تبي هذي البيانات التجريبية، احذف قسم `INSERT INTO` بآخر الملف قبل ما تشغّله، أو شغّله كذا وبعدين احذفها لاحقاً باستيراد بياناتك الحقيقية (الخطوة 4 بالأسفل تمسحها تلقائياً على أي حال).

للتأكد إن الجداول انشأت صح، بالقائمة الجانبية اليسرى بـ Supabase اضغط على أيقونة **Table Editor** وشوف الجداول الأربعة.

---

## 2) خذ رابط الاتصال (Connection String)

من نفس مشروع Supabase:
- روح **Project Settings** (⚙️ بالقائمة الجانبية) → **Database**.
- تحت "Connection string" اختر تبويب **Node.js** (أو URI).
- انسخ الرابط — شكله:
  ```
  postgresql://postgres:[YOUR-PASSWORD]@db.xxxxxxxxxxxx.supabase.co:5432/postgres
  ```
- استبدل `[YOUR-PASSWORD]` بكلمة مرور قاعدة البيانات (اللي حطيتها وقت إنشاء المشروع — لو نسيتها، فيه زر "Reset database password" بنفس الصفحة).

احتفظ بهذا الرابط، بتحتاجه بالخطوة 5.

---

## 3) إكمال رفع الكود على GitHub

أنت فاتح صفحة "Create a new repository" — أكمل:
1. اكتب اسم بخانة **Repository name** مثلاً `federations-platform`.
2. خلّه **Public** (أو Private إذا تفضل).
3. اترك "Add README" و"Add .gitignore" **مطفّية** (Off) — عشان ما يصير تعارض مع ملفاتنا.
4. اضغط **Create repository**.

بعدها بتوصلك صفحة فيها أوامر جاهزة تحت عنوان "…or push an existing repository from the command line" — افتح الترمينال بجهازك داخل مجلد المشروع (بعد فك الضغط) ونفّذ:

```bash
cd federations-platform
git init
git add .
git commit -m "النسخة الأولى: منصة متصلة بـ Supabase"
git remote add origin https://github.com/MAlsaqladi/federations-platform.git
git branch -M main
git push -u origin main
```
(غيّر الرابط بالسطر الرابع لنفس الرابط اللي عطاك ياه GitHub بصفحتك).

> ملف `.gitignore` أصلاً مُجهّز بحيث ما يرفع `node_modules/` ولا `.env` (فيها كلمة مرور قاعدة البيانات) — لا تحذفه.

---

## 4) استيراد بياناتك الحقيقية من ملف الإكسل (اختياري لكن موصى به)

بدل ما تكتب البيانات يدوياً بـ Supabase، استخدم سكربت الاستيراد الجاهز — يقرأ نفس ملف الإكسل اللي كنت ترفعه سابقاً (بنفس الأوراق: Federation_data, Activities_data, Financial_data, Reviewer) ويحطه مباشرة بقاعدة بيانات Supabase:

```bash
# أول مرة فقط:
npm install
cp .env.example .env
# افتح .env وحط رابط الاتصال من الخطوة 2 مكان DATABASE_URL

node server/import-from-excel.js "مسار/ملف/بياناتك.xlsx"
```

⚠️ هذا السكربت **يمسح** البيانات الموجودة بالجداول الأربعة (تشمل بيانات schema.sql التجريبية) ثم يستورد من جديد — استخدمه كل مرة تحدّث فيها البيانات من نسخة إكسل جديدة.

---

## 5) نشر السيرفر (الجزء اللي يشغّل الكود ويتصل بـ Supabase)

بما أن GitHub لا يشغّل Node.js، اختر واحدة من هذي (فيها باقة مجانية تكفي البداية):

### الخيار الأسهل: Render (render.com)
1. سجّل حساب واربطه بحساب GitHub تبعك.
2. **New** → **Web Service** → اختر المستودع اللي رفعته (`federations-platform`).
3. Build Command: `npm install`
4. Start Command: `npm start`
5. في قسم **Environment Variables** ضيف:
   - `DATABASE_URL` = رابط الاتصال من Supabase (الخطوة 2)
   - `JWT_SECRET` = أي نص عشوائي طويل وسرّي (غيّره عن القيمة التجريبية)
6. اضغط **Deploy** — بعد دقائق بيعطيك رابط مثل `https://federations-platform.onrender.com`.

### أو: Railway (railway.app)
نفس الفكرة — Deploy from GitHub repo، وأضف نفس متغيرَي `DATABASE_URL` و`JWT_SECRET` من تبويب Variables.

بعد النشر، افتح الرابط اللي عطوك ياه — نفس شاشة تسجيل الدخول لازم تطلع، بس الآن متصلة بقاعدة بياناتك على Supabase مباشرة من الإنترنت.

جرّب الدخول ببيانات الاتحادات التجريبية (إذا أبقيت بيانات schema.sql التجريبية):
- **دخول كاتحاد**: `user1` / `pass1`
- **دخول كمراجع**: `f` / `123456` (نوعه "مراجع")، أو `r` / `111111` (نوعه "مدير" — وصول كامل)

---

## 6) تحديث لاحق

كل مرة عندك نسخة إكسل جديدة: شغّل `node server/import-from-excel.js "ملفك.xlsx"` وأنت متصل بـ `.env` اللي فيه رابط Supabase الحقيقي.

كل مرة تعدّل كود (الواجهة أو السيرفر):
```bash
git add .
git commit -m "وصف التعديل"
git push
```
Render وRailway يعيدون النشر تلقائياً بمجرد ما يشوفون push جديد على GitHub.

---

## ملاحظات أمان مهمة قبل الاستخدام الفعلي

- **كلمات المرور مخزّنة حالياً كنص عادي** (نفس ما كانت بالإكسل) لتسهيل الانتقال. للاستخدام الجدّي يُفضّل تشفيرها بـ `bcrypt` — إذا احتجت هذا التحسين قله لي وأساعدك فيه.
- غيّر `JWT_SECRET` بمنصة الاستضافة لقيمة عشوائية طويلة (لا تستخدم القيمة التجريبية).
- لا ترفع ملف `.env` أبداً لـ GitHub (محمي أصلاً بـ `.gitignore`).
